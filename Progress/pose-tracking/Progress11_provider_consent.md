# Provider launch protection and consent

Hosted PoseTracker launch is now disabled unless the main API environment explicitly sets `POSETRACKER_ENABLED=true`; this applies to normal and administrator provider launches and to the native SDK launch that obtains its credential from the same endpoint. Generated-angle launches return before the provider switch. Disabling the switch cannot invalidate a previously disclosed credential or stop an existing session.

`frontend/sections/Coach/PoseTrackerSession.tsx` now displays a third-party camera and data-use notice, a provider privacy-policy link, and a session-specific agreement checkbox. The launch action is disabled and guarded until consent; stop and interruption clear it. The same UI gates the native SDK and admin-test paths. Consent is session-local and is not persisted. No claim is made that this UI constitutes a legal consent record.

Provider scope and short-lived token support remain NOT VERIFIED. The repository's `output/posetracker-api-key.md` and `output/posetracker-webview-query-params.md` describe a required browser-visible dashboard key for the hosted tracking URL. Attempts to open current official documentation using the web tool returned inaccessible errors. The provider credential is still returned by the launch API and included in the hosted iframe URL when explicitly enabled; no unsupported token exchange or provider restriction was invented. The kill switch reduces exposure by default but does not make that token secret.
