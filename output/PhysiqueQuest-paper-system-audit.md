## How to use this review

- **Paper correction:** the claim conflicts with inspected current code or another part of the paper. Revise the paper to describe the actual system.
- **Decision:** the paper promises something not found in the inspected implementation. The team and adviser must either implement and test it or remove/narrow the promise. This review does not recommend pretending a feature exists.
- **Verification:** a capability exists in code, but implementation, live deployment, user outcomes, or safety/accuracy are not established by code alone.
- **Formatting:** document, figure, or methodological issue independent of software implementation.

This is an evidence-based audit, not a legal, clinical, or ISO certification assessment. It compares the PDF with relevant code, configuration, repository reports, and the already observed Android build/install. It does not establish production credentials, live provider behavior, actual database contents, field-study responses, or physical-device performance. Literature citations were not independently checked against original publications. Images and tables were visually inspected for representative diagram pages; exact figure contents and every field in the 80-plus-page dictionary still need individual re-verification when the authors regenerate them.
